# Domain docs

This repository uses a single domain context.

Before work that uses domain terms, read the root `GLOSSARY.md` if it exists. Read relevant decisions in `docs/adr/` if they exist. Proceed when either is absent.

Use the glossary's terms in specs, tickets, code, and tests. Surface any conflict with an ADR explicitly. Create domain documents when terms or decisions need to be recorded, rather than as empty setup files.
